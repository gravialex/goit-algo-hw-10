# Порівняння ефективності алгоритмів видачі решти

У цьому домашньому завданні розглядаються дві реалізації для розрахунку оптимальної видачі решти покупцю за допомогою набору монет `[50, 25, 10, 5, 2, 1]`:
1. **Жадібний алгоритм** (`find_coins_greedy`)
2. **Алгоритм динамічного програмування** (`find_min_coins`)

---

## 1. Жадібний алгоритм (`find_coins_greedy`)

* **Принцип роботи:** На кожному кроці алгоритм обирає найбільший можливий номінал монети, який не перевищує залишок суми.
* **Часова складність ($O$-велике):** $O(N)$, де $N$ — кількість номіналів монет (фіксована кількість, тому складність прагне до $O(1)$ незалежно від суми).
* **Просторова складність:** $O(1)$.
* **Особливості:** Працює миттєво для будь-яких сум, але гарантує оптимальність лише для канонічних монетних систем.

---

## 2. Алгоритм динамічного програмування (`find_min_coins`)

* **Принцип роботи:** Знаходить мінімальну кількість монет методом «знизу вгору», розраховуючи оптимальні рішення для всіх проміжних сум від $0$ до `amount`.
* **Часова складність ($O$-велике):** $O(S \cdot N)$, де $S$ — сума решти, а $N$ — кількість номіналів.
* **Просторова складність:** $O(S)$ (для збереження масивів результатів підзадач).
* **Особливості:** Завжди знаходить математично мінімальну кількість монет для будь-яких наборів номіналів, проте суттєво втрачає продуктивність при великих сумах через лінійне зростання кількості операцій.

---

## Порівняння за часом виконання та результати

Нижче наведено практичні результати тестування обох алгоритмів для різних сум решти:

| Сума решти ($S$) | Жадібний алгоритм | Час (жадібний) | Динамічне програмування | Час (ДП) |
| :--- | :--- | :--- | :--- | :--- |
| **113** | `{50: 2, 10: 1, 2: 1, 1: 1}` | 0.000036 с | `{1: 1, 2: 1, 10: 1, 50: 2}` | 0.000457 с |
| **1,123** | `{50: 22, 10: 2, 2: 1, 1: 1}` | 0.000008 с | `{1: 1, 2: 1, 10: 2, 50: 22}` | 0.001936 с |
| **5,321** | `{50: 106, 10: 2, 1: 1}` | 0.000005 с | `{1: 1, 10: 2, 50: 106}` | 0.008109 с |
| **12,345** | `{50: 246, 25: 1, 10: 2}` | 0.000006 с | `{10: 2, 25: 1, 50: 246}` | 0.015292 с |
| **123,456** | `{50: 2469, 5: 1, 1: 1}` | 0.000050 с | `{1: 1, 5: 1, 50: 2469}` | 0.288089 с |

---

### Висновки щодо продуктивності:

1. **Жадібний алгоритм** демонструє надзвичайно високу та стабільну продуктивність. Час його виконання залишається мікроскопічним (долі мілісекунди) навіть для великих сум (наприклад, 123,456 виконується за 0.000050 сек), оскільки кількість операцій залежить лише від кількості номіналів.
2. **Алгоритм динамічного програмування** показує час виконання, який лінійно залежить від розміру суми ($S$). Якщо для малих сум різниця неочевидна (0.0004 с проти 0.00003 с для суми 113), то для великої суми у 123,456 час зростає до 0.288 с, що суттєво повільніше. Крім того, він вимагає значно більше оперативної пам'яті під масиви `min_coins` та `coin_used`.
3. **Загальний підсумок:** Для стандартних касових систем із канонічним набором монет жадібний алгоритм є оптимальним і єдиним раціональним вибором для великих потоків операцій. Динамічне програмування доцільно використовувати лише у випадках нетипових (неканонічних) монетних систем, де жадібний підхід дає хибні результати, за умови контролю розміру максимальної суми решти.
